# US-002.02: Merge Default Configuration Values

**Feature:** [F-002 — Configuration Management](../../F-002_CONFIGURATION_MANAGEMENT.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** repository administrator,  
**I want** optional configuration fields to receive sensible default values when I don't specify them,  
**So that** I only need to configure the fields I want to customise and can rely on secure, well-chosen defaults for everything else.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** a YAML configuration file that omits the optional `monitoring` section entirely,  
      **When** the Configuration aggregate loads and merges defaults,  
      **Then** the resulting configuration contains the `monitoring` section with `metrics_enabled: false` (or the project-defined default).

- [ ] **Given** a YAML configuration file specifies `resumption.page_size: 50` but omits `resumption.token_lifetime`,  
      **When** defaults are merged,  
      **Then** `resumption.page_size` is `50` (user's value) and `resumption.token_lifetime` is `86400` (default: 24 hours).

- [ ] **Given** a YAML configuration file provides all fields explicitly,  
      **When** defaults are merged,  
      **Then** no default values override the user-specified values — the user's configuration takes precedence over defaults in every case.

- [ ] **Given** defaults are loaded from a separate defaults definition (internal array or `config/default.yaml`),  
      **When** the merge is complete,  
      **Then** the resulting configuration is a deep merge where user values override defaults at every nesting level.

### Edge Cases

- [ ] **Given** a YAML file is completely empty (no sections at all),  
      **When** defaults are merged,  
      **Then** the resulting configuration consists entirely of default values for all optional fields, and required fields remain absent (to be caught by validation in US-002.04).

- [ ] **Given** a YAML file contains an empty section (e.g., `cache:` with no sub-keys),  
      **When** defaults are merged,  
      **Then** the section is populated with its default sub-keys (e.g., `cache.driver: file`).

### Error States

- [ ] **Given** the default values definition is valid,  
      **When** merging is performed,  
      **Then** no exceptions are thrown during the merge step itself — invalid configuration is caught later by validation (US-002.04).

## Notes

- **Dependencies**: US-002.01 (YAML loading must work before defaults can be merged).
- **Design**: See [SOFTWARE_DESIGN.md](../../../event-storming/SOFTWARE_DESIGN.md) § Context 7: Configuration Context — command "Apply Defaults (for optional fields not specified)".
- **Default values for optional fields** (to be confirmed and documented in US-002.08):
  - `resumption.page_size`: `100`
  - `resumption.token_lifetime`: `86400`
  - `cache.driver`: `file`
  - `security.force_https`: `false`
  - `logging.level`: `info`
  - `monitoring.metrics_enabled`: `false`
- **Constraints**: Deep merge strategy — nested keys are merged recursively, not replaced at the section level.
- **Estimation**: S — implement deep merge of two arrays; straightforward logic with well-defined test cases.
