# US-002.03: Substitute Environment Variables in Configuration

**Feature:** [F-002 — Configuration Management](../../F-002_CONFIGURATION_MANAGEMENT.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** DevOps engineer,  
**I want** to use environment variable placeholders (e.g., `${DB_PASSWORD}`) in the YAML configuration file,  
**So that** sensitive values like database passwords and API keys are never stored in configuration files and can be injected securely at runtime.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** a YAML configuration file contains `database.password: ${DB_PASSWORD}`,  
      **When** the environment variable `DB_PASSWORD` is set to `s3cret!`,  
      **Then** after substitution the resolved value of `database.password` is `s3cret!`.

- [ ] **Given** a YAML value contains a mix of literal text and an environment variable placeholder (e.g., `host: db-${DB_ENV}-server`),  
      **When** the environment variable `DB_ENV` is set to `production`,  
      **Then** the resolved value is `db-production-server`.

- [ ] **Given** a YAML configuration file contains multiple `${...}` placeholders across different sections (e.g., `database.password`, `security.api_key`, `cache.host`),  
      **When** all referenced environment variables are set,  
      **Then** every placeholder in every section is resolved to its corresponding environment variable value.

- [ ] **Given** environment variable substitution is applied,  
      **When** I check the order of processing,  
      **Then** substitution happens after YAML parsing but before validation — so validated values reflect the resolved environment variable values.

### Edge Cases

- [ ] **Given** a YAML value contains a literal string that looks like a placeholder but is escaped or quoted differently (e.g., `$${NOT_A_VAR}` or the project decides on an escape mechanism),  
      **When** substitution is applied,  
      **Then** the escaped placeholder is not substituted and remains as literal text.

- [ ] **Given** a YAML value is `${EMPTY_VAR}` and the environment variable `EMPTY_VAR` is set to an empty string,  
      **When** substitution is applied,  
      **Then** the resolved value is an empty string (not an error — the variable exists but is empty).

### Error States

- [ ] **Given** a YAML value contains `${UNDEFINED_VAR}` and the environment variable `UNDEFINED_VAR` is NOT set,  
      **When** substitution is attempted,  
      **Then** an `EnvironmentVariableNotFoundException` is thrown with a clear message: e.g., `"Environment variable 'UNDEFINED_VAR' referenced in configuration is not defined."`.

- [ ] **Given** multiple undefined environment variables are referenced in the YAML file,  
      **When** substitution is attempted,  
      **Then** the exception message lists ALL undefined variables (not just the first one), enabling the DevOps engineer to fix all missing variables at once.

## Notes

- **Dependencies**: US-002.01 (YAML loading — substitution processes the parsed YAML data).
- **Design**: See [SOFTWARE_DESIGN.md](../../../event-storming/SOFTWARE_DESIGN.md) § Context 7: Configuration Context — command "Apply Environment Variable Substitution".
- **Files**:
  - `src/Configuration/Exception/EnvironmentVariableNotFoundException.php`
  - Updates to `src/Configuration/Aggregate/Configuration.php`
  - Updates to `tests/Configuration/Aggregate/ConfigurationTest.php`
- **Pattern**: `${VARIABLE_NAME}` — dollar sign, opening brace, variable name (uppercase letters, digits, underscores), closing brace. Regex: `\$\{([A-Z_][A-Z0-9_]*)\}`.
- **Constraints**: Substitution must use `getenv()` or `$_ENV` (configurable). Must not expose resolved secrets in error messages or logs. Recursive substitution (a variable resolving to another `${...}`) is NOT supported in MVP.
- **Estimation**: S — regex scan + replace across all string values; one exception class.
