# US-002.01: Load YAML Configuration at Startup

**Feature:** [F-002 — Configuration Management](../../F-002_CONFIGURATION_MANAGEMENT.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** repository administrator,  
**I want** the server to load its configuration from a human-readable YAML file at startup,  
**So that** I can set up and modify the server's behaviour by editing a single file without writing code.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** a valid YAML configuration file exists at the expected path (e.g., `config/config.yaml`),  
      **When** the server starts up and the `Configuration` aggregate is constructed,  
      **Then** the YAML file is loaded and parsed into an associative array representing all configuration sections.

- [ ] **Given** the YAML file contains all required configuration sections (`repository`, `database`, `mapping`, `metadata_formats`, `resumption`, `cache`, `security`, `logging`),  
      **When** loading completes,  
      **Then** each section is accessible as an associative array and all key-value pairs are preserved exactly as specified in the YAML.

- [ ] **Given** the `Configuration` class is constructed,  
      **When** I check its namespace and class structure,  
      **Then** it is located at `src/Configuration/Aggregate/Configuration.php` in namespace `OaiPmh\Configuration\Aggregate` and implements `ConfigurationInterface` from F-001.

### Edge Cases

- [ ] **Given** the YAML file contains only some sections (others are optional),  
      **When** the file is loaded,  
      **Then** the present sections are loaded successfully without errors for the absent optional sections.

- [ ] **Given** the YAML file contains YAML comments,  
      **When** the file is parsed,  
      **Then** comments are ignored and do not affect the loaded configuration data.

### Error States

- [ ] **Given** the specified YAML file path does not exist,  
      **When** the `Configuration` aggregate tries to load it,  
      **Then** a `ConfigurationLoadException` is thrown with a clear message including the file path: e.g., `"Configuration file not found: config/config.yaml"`.

- [ ] **Given** the specified YAML file exists but is not readable (permission denied),  
      **When** the `Configuration` aggregate tries to load it,  
      **Then** a `ConfigurationLoadException` is thrown with a clear message: e.g., `"Configuration file is not readable: config/config.yaml"`.

- [ ] **Given** the YAML file contains invalid YAML syntax (e.g., malformed indentation, missing colon),  
      **When** the file is parsed,  
      **Then** a `ConfigurationLoadException` is thrown with a message that includes the YAML parse error detail.

## Notes

- **Dependencies**: F-001/US-001.07 (`ConfigurationInterface` must be defined).
- **Design**: See [SOFTWARE_DESIGN.md](../../../event-storming/SOFTWARE_DESIGN.md) § Context 7: Configuration Context — Configuration aggregate, command "Load Configuration".
- **Files**:
  - `src/Configuration/Aggregate/Configuration.php`
  - `src/Configuration/Exception/ConfigurationLoadException.php`
  - `tests/Configuration/Aggregate/ConfigurationTest.php`
- **Constraints**: YAML parsing should use a lightweight PHP library (e.g., Symfony YAML component). No external admin UI; YAML files are the only configuration mechanism for MVP.
- **Estimation**: S — single file load, parsing, and exception handling. The `Configuration` class skeleton is created here; later stories add validation, defaults, and immutability.
