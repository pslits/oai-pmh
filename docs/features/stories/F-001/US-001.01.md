# US-001.01: Project Namespace and Directory Scaffolding

**Feature:** [F-001 — Project Foundation & Shared Contracts](../../F-001_PROJECT_FOUNDATION_AND_SHARED_CONTRACTS.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** core developer,  
**I want** a well-defined namespace structure and skeleton directory layout for all seven bounded contexts,  
**So that** I can begin implementing each context in isolation without namespace conflicts or ambiguity about where new code belongs.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** the project has seven bounded contexts (Protocol, Repository, MetadataSerialization, AccessControl, FlowControl, Observability, Configuration) plus Infrastructure,  
      **When** I check `composer.json`,  
      **Then** each context has a dedicated PSR-4 namespace entry mapping to its `src/` subdirectory (`OaiPmh\Protocol\ → src/Protocol/`, etc.)

- [ ] **Given** the namespace entries are registered,  
      **When** I run `composer dump-autoload`,  
      **Then** all 8 new namespaces resolve correctly and no autoload errors are reported.

- [ ] **Given** the skeleton directory tree is created,  
      **When** I browse `src/`,  
      **Then** each bounded context has at minimum `Contract/` and `Aggregate/` subdirectories, plus context-specific subdirectories per the technical design (e.g., `Repository/Entity/`, `Repository/Service/`, `Infrastructure/Cache/`, `Infrastructure/Database/`).

### Edge Cases

- [ ] **Given** the existing `src/Domain/ValueObject/` directory already has 23 classes,  
      **When** the new namespace entries are added to `composer.json`,  
      **Then** the existing `OaiPmh\` root namespace autoloading is preserved and none of the 23 value objects break.

### Error States

- [ ] **Given** a developer references a class from a new namespace (e.g., `OaiPmh\Repository\Contract\RecordInterface`),  
      **When** the interface file does not yet exist but the namespace is registered,  
      **Then** PHP throws a class-not-found error (not an autoload configuration error), confirming the autoloader is correctly configured.
