# US-001.04: Authentication Provider Contract

**Feature:** [F-001 — Project Foundation & Shared Contracts](../../F-001_PROJECT_FOUNDATION_AND_SHARED_CONTRACTS.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** security developer,  
**I want** a clearly defined `AuthenticationProviderInterface` contract in the AccessControl context,  
**So that** I can implement custom authentication mechanisms (Basic Auth, API key, SSO) against a stable interface without modifying the server's core authentication pipeline.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** the AccessControl bounded context exists at `src/AccessControl/Contract/`,  
      **When** I open `AuthenticationProviderInterface.php`,  
      **Then** it defines a PHP interface in namespace `OaiPmh\AccessControl\Contract` with methods for: authenticating an incoming request, checking whether authentication is required, and retrieving the authenticated identity.

- [ ] **Given** the interface is defined,  
      **When** I implement a Basic Auth provider,  
      **Then** the interface contract is sufficient to extract credentials from the request, validate them, and return an identity — without prescribing how credentials are stored or validated.

- [ ] **Given** the interface is defined,  
      **When** I review the docblocks,  
      **Then** every method has a complete docblock with `@param`, `@return`, and `@throws` annotations, explaining the authentication lifecycle (authenticate → identity or failure).

### Edge Cases

- [ ] **Given** the server is configured for public access (no authentication),  
      **When** I check the interface,  
      **Then** it supports a "no-op" implementation where authentication is skipped and all requests are treated as anonymous — the interface does not force authentication.

### Error States

- [ ] **Given** a request contains invalid or missing credentials,  
      **When** authentication is attempted,  
      **Then** the interface documents (via `@throws`) that an authentication exception is thrown, enabling the middleware to return HTTP 401 Unauthorized.

---

## Notes

- **Dependencies**: US-001.01 (namespace scaffolding).
- **Design**: See [SOFTWARE_DESIGN.md](../../../docs/event-storming/SOFTWARE_DESIGN.md) § Context 4: Access Control Context — Authenticator aggregate. MVP uses public access (no auth) by default; this interface enables post-MVP authentication plugins.
- **Constraints**: Interface must not depend on a specific HTTP library. Request data should be passed as typed parameters or a PSR-7-compatible abstraction. Must support multiple simultaneous auth providers.
- **Estimation**: S — one interface with 3–4 methods; straightforward auth lifecycle pattern.
