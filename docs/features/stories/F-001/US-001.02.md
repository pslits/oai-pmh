# US-001.02: Repository Data Access Contracts

**Feature:** [F-001 — Project Foundation & Shared Contracts](../../F-001_PROJECT_FOUNDATION_AND_SHARED_CONTRACTS.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** database adapter developer,  
**I want** clearly defined `RecordInterface` and `StorageAdapterInterface` contracts in the Repository context,  
**So that** I can implement MySQL, PostgreSQL, or other storage adapters against stable, well-documented interfaces without coupling to a specific database implementation.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** the Repository bounded context exists at `src/Repository/Contract/`,  
      **When** I open `RecordInterface.php`,  
      **Then** it defines a PHP interface in namespace `OaiPmh\Repository\Contract` with methods to access record data: retrieve identifier, datestamp, set memberships, deletion status, and metadata content.

- [ ] **Given** the Repository bounded context exists at `src/Repository/Contract/`,  
      **When** I open `StorageAdapterInterface.php`,  
      **Then** it defines a PHP interface in namespace `OaiPmh\Repository\Contract` with methods for querying records: find by identifier, list with filters (metadataPrefix, from, until, set), count results, and determine earliest datestamp.

- [ ] **Given** both interfaces are defined,  
      **When** I implement a class that satisfies `RecordInterface`,  
      **Then** the interface contract is sufficient to represent any metadata record regardless of storage backend (MySQL, PostgreSQL, file-based).

- [ ] **Given** both interfaces are defined,  
      **When** I review the docblocks,  
      **Then** every method has a complete docblock with `@param`, `@return`, and `@throws` annotations, and the class-level docblock references the OAI-PMH 2.0 specification sections for records and data providers.

### Edge Cases

- [ ] **Given** a record may be marked as deleted,  
      **When** I check `RecordInterface`,  
      **Then** it provides a method to determine deletion status, aligning with the OAI-PMH deletedRecord policy (no/transient/persistent).

### Error States

- [ ] **Given** `StorageAdapterInterface` defines a method to find a record by identifier,  
      **When** the identifier does not exist in the repository,  
      **Then** the interface documents (via `@throws`) that an appropriate exception is thrown, not a null return.

## Notes

- **Dependencies**: US-001.01 (namespace scaffolding must exist).
- **Design**: See [SOFTWARE_DESIGN.md](../../../docs/event-storming/SOFTWARE_DESIGN.md) § Context 2: Repository Context — Record and RecordCollection aggregates define the domain model these interfaces abstract.
- **Constraints**: Interfaces must use existing domain value objects (`RecordIdentifier`, `UTCdatetime`, `SetSpec`, `MetadataPrefix`) as parameter/return types where appropriate. Must follow Dependency Inversion Principle — domain layer depends on these interfaces, infrastructure implements them.
- **Estimation**: S — two concise interfaces with well-known method signatures derived from OAI-PMH spec.
