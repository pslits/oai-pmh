# US-001.09: Quality Gate and Regression Verification

**Feature:** [F-001 — Project Foundation & Shared Contracts](../../F-001_PROJECT_FOUNDATION_AND_SHARED_CONTRACTS.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** core developer,  
**I want** all new interface files to pass PHPStan Level 8 and PSR-12 checks, and the existing test suite to remain green,  
**So that** I have confidence that the shared contracts are type-safe, standards-compliant, and the foundation work introduced no regressions.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** all 9 interface files have been created across the bounded contexts,  
      **When** I run `vendor/bin/phpstan analyse`,  
      **Then** PHPStan Level 8 reports zero errors for both the new interface files and all existing code.

- [ ] **Given** all 9 interface files have been created,  
      **When** I run `vendor/bin/phpcs`,  
      **Then** PHP_CodeSniffer reports zero PSR-12 violations for all new files.

- [ ] **Given** all new files have been added to the project,  
      **When** I run `vendor/bin/phpunit`,  
      **Then** the entire existing test suite (28+ test files, 200+ assertions) passes with zero failures and zero errors.

- [ ] **Given** all interface files are syntactically valid,  
      **When** I run `php -l` (lint) on each new file,  
      **Then** every file reports "No syntax errors detected."

### Edge Cases

- [ ] **Given** new interfaces reference domain value objects (e.g., `RecordIdentifier`, `MetadataPrefix`),  
      **When** PHPStan analyses these type hints,  
      **Then** all cross-namespace references resolve correctly and no "class not found" warnings appear.

### Error States

- [ ] **Given** a developer accidentally introduces a type error in an interface (e.g., incompatible return type),  
      **When** PHPStan is run,  
      **Then** the error is caught at Level 8 and reported with the file name and line number, preventing the issue from reaching other developers.

## Notes

- **Dependencies**: US-001.01 through US-001.08 (all stories must be complete before this verification pass).
- **Design**: This is a verification story, not a feature story. It ensures the quality gates defined in the project standards are met for all foundation work.
- **Constraints**: PHPStan configuration is in `phpstan.neon` at the project root. PHPCS configuration is in `phpcs.xml`. Both already target Level 8 and PSR-12 respectively. No new tools or configurations should be needed.
- **Estimation**: S — run existing tools, fix any issues found. Primarily a verification pass.
