# US-001.05: Infrastructure Storage Contracts

**Feature:** [F-001 — Project Foundation & Shared Contracts](../../F-001_PROJECT_FOUNDATION_AND_SHARED_CONTRACTS.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As an** infrastructure developer,  
**I want** clearly defined `TokenStorageInterface` and `CacheInterface` contracts for storage backends,  
**So that** I can implement Redis, file-based, or other storage adapters for resumption tokens and response caching without coupling to a specific backend technology.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** the FlowControl bounded context exists at `src/FlowControl/Contract/`,  
      **When** I open `TokenStorageInterface.php`,  
      **Then** it defines a PHP interface in namespace `OaiPmh\FlowControl\Contract` with methods for: storing a resumption token, retrieving a token by its key, deleting a token, and checking if a token exists.

- [ ] **Given** the Infrastructure context exists at `src/Infrastructure/Contract/`,  
      **When** I open `CacheInterface.php`,  
      **Then** it defines a PHP interface in namespace `OaiPmh\Infrastructure\Contract` with methods for: getting a cached value by key, setting a value with optional TTL, deleting a cached value, checking existence, and clearing the entire cache.

- [ ] **Given** both interfaces are defined,  
      **When** I implement a Redis-backed token storage,  
      **Then** the `TokenStorageInterface` contract is sufficient to persist and retrieve resumption token state without exposing Redis-specific details.

- [ ] **Given** both interfaces are defined,  
      **When** I review the docblocks,  
      **Then** every method has a complete docblock with `@param`, `@return`, and `@throws` annotations.

### Edge Cases

- [ ] **Given** `TokenStorageInterface` defines a retrieve method,  
      **When** a token has expired (past its configured lifetime),  
      **Then** the interface documents the expected behavior: return null or throw an exception, enabling callers to distinguish "not found" from "expired."

### Error States

- [ ] **Given** `CacheInterface` defines a `get` method,  
      **When** the cache backend is unavailable (e.g., Redis is down),  
      **Then** the interface documents (via `@throws`) the expected exception type so the application can degrade gracefully to uncached operation.

---

## Notes

- **Dependencies**: US-001.01 (namespace scaffolding).
- **Design**: See [SOFTWARE_DESIGN.md](../../../docs/event-storming/SOFTWARE_DESIGN.md) § Context 5: Flow Control Context (ResumptionToken aggregate) and § Architecture Notes. `CacheInterface` aligns with PSR-16 (Simple Cache) semantics but is defined as a project-owned contract to avoid hard coupling to `psr/simple-cache`.
- **Constraints**: `TokenStorageInterface` must support token lifetime/expiration. `CacheInterface` should be PSR-16-compatible in spirit but may have a narrower scope (no multi-get/multi-set unless needed). Neither interface should reference a specific backend technology.
- **Estimation**: S — two concise interfaces with standard get/set/delete/exists patterns.
