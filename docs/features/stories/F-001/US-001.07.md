# US-001.07: Configuration Contract

**Feature:** [F-001 — Project Foundation & Shared Contracts](../../F-001_PROJECT_FOUNDATION_AND_SHARED_CONTRACTS.md)  
**Priority:** MVP (MUST HAVE)  
**Estimation:** S (0.5–1 day)  
**Status:** Draft  
**Date:** February 18, 2026  

---

## Story

**As a** core developer,  
**I want** a clearly defined `ConfigurationInterface` contract in the Configuration context,  
**So that** all bounded contexts can access validated, immutable configuration through a single predictable contract, enabling multiple configuration backends (YAML, environment variables, in-memory) without changing consumer code.

---

## Acceptance Criteria

### Happy Path

- [ ] **Given** the Configuration bounded context exists at `src/Configuration/Contract/`,  
      **When** I open `ConfigurationInterface.php`,  
      **Then** it defines a PHP interface in namespace `OaiPmh\Configuration\Contract` with methods for: retrieving a configuration value by key, retrieving a typed section (e.g., `getSection('database')`), checking if a key exists, and getting all configuration as an array.

- [ ] **Given** the interface is defined,  
      **When** a bounded context needs configuration (e.g., Repository context needs database credentials),  
      **Then** it depends only on `ConfigurationInterface` — not on YAML parsing, file loading, or environment variable resolution.

- [ ] **Given** the interface is defined,  
      **When** I review the docblocks,  
      **Then** every method has a complete docblock with `@param`, `@return`, and `@throws` annotations, and the class-level docblock explains that configuration is immutable after server startup.

### Edge Cases

- [ ] **Given** `ConfigurationInterface` defines a `get` method with a key parameter,  
      **When** I request a configuration value that has a default,  
      **Then** the interface supports providing a default value parameter, returning it when the key is absent (similar to `get(string $key, mixed $default = null)`).

### Error States

- [ ] **Given** `ConfigurationInterface` defines a `get` method,  
      **When** a required configuration key is missing and no default is provided,  
      **Then** the interface documents (via `@throws`) that an `InvalidConfigurationException` is thrown with a message specifying which key is missing.

---

## Notes

- **Dependencies**: US-001.01 (namespace scaffolding).
- **Design**: See [SOFTWARE_DESIGN.md](../../../docs/event-storming/SOFTWARE_DESIGN.md) § Context 7: Configuration Context — the Configuration aggregate. Configuration is foundational: all other contexts depend on it. Loaded once at startup, immutable thereafter.
- **Constraints**: Must not expose file paths, YAML details, or environment variable mechanics. Sections must align with the configuration sections defined in the technical design: `repository`, `database`, `mapping`, `metadata_formats`, `resumption`, `cache`, `security`, `logging`, `monitoring`. The existing `InvalidConfigurationException` in `src/Domain/Exception/` should be used (or referenced) for validation failures.
- **Estimation**: S — one interface with 4–5 methods; clear key-value access pattern.
